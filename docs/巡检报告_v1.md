# 巡检报告 v1（稳定性优先）

- 巡检日期：2026-02-22
- 范围：`$HOME/选题插件开发/backend`、`$HOME/选题插件开发/frontend`
- 目标：先稳定、后体验；避免双前端并行演进。

## 1. 总体结论

当前系统可用，但存在以下高优先风险：

1. 前端实现分叉导致回归风险高。
2. 抓取触发链路未统一排队，可能并发冲突。
3. 单次抓取覆盖参数若写全局会污染其他任务。
4. 回调安全边界与异常可观测性不足。

## 2. 本轮已完成修复（P0）

1. **任务模型统一**
- 新增 `ScrapeTask` 表，记录 `queued/running/success/failed` 生命周期。
- 手动触发、飞书触发、定时触发统一入队，串行执行。

2. **接口升级**
- `POST /api/scrape/trigger` 改为返回任务信息：`task_id/queued_at/position`。
- 新增 `GET /api/tasks`、`GET /api/tasks/{task_id}`。

3. **覆盖参数隔离**
- 单次 `scrape_headless` 仅作为任务上下文，不再改全局配置。
- 运行时通过 scraper override 注入，并在任务结束后清理。

4. **回调安全增强**
- 飞书回调加入时间窗校验、签名校验、nonce 重放防护。
- 支持配置签名密钥（`TA_FEISHU_EVENT_SIGNING_SECRET`）。

5. **错误结构统一**
- HTTP 异常统一输出结构化错误：`code/message/hint/request_id`。
- 增加系统兜底异常处理和 `X-Request-Id` 响应头。

6. **前端入口收敛**
- `frontend/src/main.js` 调整为壳层重定向到后端 `/dashboard`。
- 目标：保留唯一控制台实现源，降低维护成本。

## 3. 当前剩余风险（进入 P1）

1. 任务执行仍为单进程内队列，后续可迁移到 Redis/BullMQ/Prefect。
2. 回调签名目前为兼容模式，正式上线建议按飞书最终配置固定算法。
3. 端到端 UI 自动化用例尚缺，建议补 Playwright 冒烟。
4. 进程守护与隧道保活仍需标准化（systemd/supervisor）。

## 4. 验收建议

1. 并发触发 10 次，确认始终只有 1 个 `running`。
2. 同时下发不同 `scrape_headless` 任务，确认互不污染。
3. 关闭/错误签名回调请求被拒绝，合法请求通过。
4. 前端仅通过 `/dashboard` 实现任务、历史、配置全流程。
